## Git 同步故障诊断与修复 (Bangumi-Archive-Anime-Excel)
- 现象：IDE 后台 git fetch/pull 反复失败（schannel SSL 握手失败 / curl56 early EOF），`origin/main` 引用反复消失（`[gone]`）。
- 根因1：GitHub HTTPS（schannel）在本机网络不稳，间歇性失败；当前已恢复。
- 根因2：IDE 后台 Git 自动 fetch 会把 `refs/remotes/origin/main` 清掉（显示 [gone]），手动 update-ref 也会被冲掉——属表象问题，推送时 IDE 会重建。
- 关键坑：`git checkout/reset/rebase` 切到远程 a696ae2 时，会把 4 个旧差异文件夹（2026-07-21..08-11）从工作树**整目录删除**（blob/树完整、ls-tree 确认存在，但 checkout 写不回磁盘）——疑似 Windows + core.autocrlf=true + 文件被编辑器占用导致 rename 失败。rebase 因此被 git 拒绝（“有未暂存改动”），实则保护数据。
- 解决方案：用 `git merge a696ae2`（而非 rebase）把远程并入本地，只合并 README.md 徽章改动，不重置工作树，文件不丢。已生成合并提交 d4d61a7，本地领先远程 2 提交，待用户在 IDE 推送。
- 建议：该仓库可考虑设 `core.autocrlf=false` 或加 `.gitattributes` 强制 eol=lf，规避 checkout 异常；推送前在 IDE 关闭 Git 自动 fetch / 自动 pull-rebase 以免竞态。
